Back of house

The kitchen behind the menu.

How a mood typed on a phone becomes a recommendation that streams back word by word. GameGusto is a Claude agent on Amazon Bedrock with a small serverless stack around it, all in one AWS region, all defined in Terraform, and scaled to zero when nobody is ordering.

eu-north-1 region 9 AWS services 27 stack resources 18 API routes 11 agent tools 260 tests 81 games in the live library
The floor plan

One request, end to end

CloudFront is the only public door. It serves the app from a private S3 bucket and forwards /api/* to a Lambda function. Inside the function, the agent calls Bedrock, the database and two outside APIs.

Why a Function URL and an adapter

API Gateway and the usual Mangum bridge both buffer the whole response. The Lambda Web Adapter runs a normal uvicorn server and streams its output.

Why nothing is public

The S3 bucket blocks public access and the Function URL requires IAM auth. CloudFront signs every origin request with Origin Access Control.

Why one region

One user in Denmark. eu-north-1 keeps the data in the EU; CloudFront's PriceClass_100 edges cover Europe and North America.

On the line

One chat turn, token by token

The backend is a FastAPI app wrapped around a tool-using agent. The model decides which tools to call; the code decides how many rounds it gets and streams everything it does back to the phone as it happens.

The pass

A PWA with two runtime dependencies

React 18 and TypeScript, built with Vite, installed from the browser like an app. The only runtime packages are react and react-dom.

The ID token travels in X-Id-Token; every request with a body carries its SHA-256 in x-amz-content-sha256.

Three service-worker rules

  • Never touch /api/*. Intercepting it would break the stream and cache responses that must stay live.
  • Navigations go to the network first. A stale index.html would pin the app to an old build after a deploy.
  • Cache the shell and its bundles together. Caching bundles lazily can leave an offline page pointing at scripts it never stored.

Sign-in is not partitioning

Cognito proves who is asking, but storage always uses USER#default, so every account shares one library. Splitting it is a data migration, written up in docs/adding-users.md.

The table lives outside Terraform

It holds the only data that can't be rebuilt. The deploy role can only describe it, so no plan or apply can ever replace it.

The brigade

Five layers, and imports only point down

Each layer may use the ones below it and never the ones above. The web app talks to the API over HTTP only. Bars show lines of code, all on one scale.

Who holds the keys

Two Terraform roots, two levels of trust

Infrastructure is split so that the everyday deploy credentials cannot give themselves more power or touch the data.

bootstrap
Applied rarely, by the owner with admin rights, using local state. Creates the deploy role, its permissions boundary, the Terraform user and the encrypted, versioned state bucket.
stack
Applied on every deploy, as gamegusto-deploy, with state in S3. Owns the 27 resources in the diagram above.
runtime role
The Lambda can invoke Anthropic models on Bedrock, read and write items in the one table, read parameters under /gamegusto/, and write logs. Nothing else.
secrets
Kept in SSM SecureStrings and read at cold start. They are never Terraform variables and never printed.

What the deploy role is denied

  • Changing its own controls: its policy, its role and the boundary.
  • The live table, beyond describing it.
  • Creating roles without the boundary, so it cannot mint a stronger role.
  • Passing roles to anything but Lambda.

infra/bootstrap/verify_policy.py evaluates the policy against 20 expected allow/deny decisions after every change.

Hard lessons

Six constraints, each found in production

The stream arrived all at once

cause
API Gateway and Mangum buffer the full response; so does CloudFront compression.
fix
Function URL in RESPONSE_STREAM mode behind the Web Adapter, compression off on /api/*.

Every API call failed its signature

cause
Origin Access Control puts its own SigV4 signature in Authorization.
fix
The token travels as X-Id-Token; requests with a body send their payload hash.

CloudFront got 403 from Lambda

cause
Invoking a Function URL through OAC needs two permissions, not one.
fix
Grant CloudFront both InvokeFunctionUrl and InvokeFunction.

Every Xbox game returned 404

cause
CloudFront decodes %2F, so "X/S" in a path split the route.
fix
Record keys move into the request body for every record action.

API errors came back as HTML 200s

cause
A distribution-wide custom error page also rewrote API failures.
fix
A CloudFront Function does SPA routing on the S3 behaviour only.

No cover ever came from IGDB

cause
The filter category = 0 matched nothing, so every lookup fell back silently.
fix
Filter on parent_game and version_parent, then rank by name.
Opening the kitchen

make deploy, in five steps

  1. Build the Lambda zip make api-build

    uv installs manylinux x86_64 wheels for Python 3.13 next to the app code. The Gmail libraries stay out.

  2. Apply the stack terraform apply

    Runs as gamegusto-deploy. The zip goes to the artifacts bucket under its content hash and the function points at it. New containers read their keys from SSM on cold start.

  3. Build the web app make web-build

    Vite builds the PWA with the Cognito domain and client ID taken from the Terraform outputs.

  4. Upload it aws s3 sync

    Hashed assets get a one-year immutable cache. index.html, the manifest and sw.js are uploaded with no-cache.

  5. Invalidate the entry points cloudfront create-invalidation

    Only the three no-cache files. Installed apps pick up the new service worker the next time they open.

Health inspection

More test code than application code

260tests in the default run
93%line coverage, 85% floor
0mypy errors
5files of Hypothesis property tests
  • make check must pass before every PR: ruff format, ruff lint, mypy and pytest with the coverage floor.
  • Property tests encode the spec's correctness properties, such as the search rate limit holding for any sequence of calls.
  • Fakes reproduce real failure modes. A fake that always succeeds cannot test the error path the user actually sees.
  • A pre-commit hook runs ruff and mypy on every commit; main only changes through reviewed pull requests.
